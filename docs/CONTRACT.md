# Gallery contract — content format & publishing (v1)

Shared by the site (repo `jordarmoin/Yu-Heng`) and the console/publisher (workbench repo). Change only with the creative lead.

## Server locations
- Site repo working clone: `/var/lib/codex-workbench/projects/yu-heng` (remote `origin` = GitHub `jordarmoin/Yu-Heng`, branch `main`).
- Masters (originals, never published, may exceed 25 MB): `/var/lib/codex-workbench/gallery/masters/<work-path>/`.
- Console publisher state/lock/log: `/var/lib/codex-workbench/gallery/state/`.
- Credentials: `/etc/codex-workbench/gallery.env` (root:root 0600), read only by the publisher. Never committed, logged or echoed.

## Repo layout
```
content/site.yaml                       # intro {zh,en}, signature, links
content/works/<slug>/item.yaml          # one item = one folder; nesting = sub-folders with their own item.yaml
content/works/<slug>/media/…            # web-ready derivatives only (generated by scripts/media.*), all files < 24 MB
content/works/<slug>/files/…            # downloadable files listed in the card's file tree
site/ (Astro, static output) · scripts/ · package.json   → `npm ci && npm run build` → `dist/`
```

```yaml
  - template: hero-note
    text: {zh: …, en: …}
    pieces: [{src: …, poster: …, alt: {…}, name: {…}, note: {zh: …, en: …}}]

  - {path: files/stickers.zip, kind: bundle}
```
Transparency is detected at build, never stored. Unknown keys are ignored (forward compatible).

## Publishing (single trigger — decided)
- Drafts live only on the server. GitHub receives a commit **only when the owner presses Publish**: exactly one commit per
  publish, message `publish: <short summary>`, plus an annotated tag `publish-YYYYMMDD-HHMMSS`.
- **EdgeOne deploys from its Git integration on push to `main`. The server never triggers an EdgeOne deployment.** It uses the
  EdgeOne API read-only to find the deployment for the pushed commit SHA and report queued/building/success/failed + URL
  (timeout 20 min).
- Before pushing: run the same `npm run build` locally (this is also the console preview) and the 24 MB file check; refuse to
  push on failure. `git fetch` + fast-forward check; a single publish lock.
- Rollback = new commit restoring `content/` (and `site/` if chosen) from a chosen tag, then the same publish flow. History
  is never rewritten, no force pushes.
